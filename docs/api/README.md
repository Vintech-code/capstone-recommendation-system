# API catalogue

The authoritative API is Laravel under `/api/v1`. Browser authentication uses stateful Sanctum cookies and CSRF protection.

| Group | Main capabilities | Access |
| --- | --- | --- |
| `/auth` | split-name Student registration, email verification/resend, login, session, logout, password recovery/change, Administrator invitation preview/acceptance, portal authorization | mixed public/authenticated; throttled where sensitive |
| `/student/assessments/riasec` | questionnaire, current session, save, submit, retry, history | active Student |
| `/student/entrance-examination` | read/create self-declaration | active Student |
| `/student/recommendations` | latest and historical attempt snapshots; private per-programme interest-match feedback | owning active Student |
| `/student/programmes` | catalogue and programme detail | active Student |
| `/student/saved-programmes` | list, save, remove | owning active Student |
| `/student/profile` | personal and academic profile, required eight-digit ID number, read-only RIASEC summary, and profile photo | owning active Student |
| `/admin` | overview, Students, programmes, ESCO, catalogue configuration, reports, activity | active Administrator |
| `/admin/administrators` | list accounts/invitations, invite, resend/revoke, suspend/reactivate, manage account capability, revoke sessions | active Administrator with account-management capability; throttled and password-confirmed for mutations |
| `/locations` | locally synced PSGC hierarchy | active authenticated account; throttled |

Google OAuth redirects are web routes under `/auth/google/*`. The redirect accepts a validated `portal` hint, always asks Google to show the account chooser, and preserves the selected portal through the callback. Student OAuth may create or link a Student account; Administrator OAuth only links a matching existing active Administrator and never grants the Administrator role. `GET /` returns API service metadata, and `/up` is Laravel's health route.

`POST /api/v1/auth/register` requires `firstName`, `lastName`, `email`, `password`, and `password_confirmation`. It creates an unverified Student and sends Laravel's signed verification notification. `GET /auth/email/verify/{id}/{hash}` is signed and expiring, marks ownership verified, and returns to Student sign-in. `POST /api/v1/auth/email/verification-notification` resends without account enumeration. Password login returns `EMAIL_NOT_VERIFIED` until verification succeeds, and protected domain routes also enforce the `verified` middleware.

Run `php artisan route:list --except-vendor` from `apps/backend` for the exact current method, URI, action, and middleware mapping. Controllers return JSON and React consumes the `data` envelope for domain endpoints.

The 2026-09-16 contract cleanup removed unused duplicate endpoints for `/auth/me`, direct score-only RIASEC results, the profile RIASEC-result alias, configuration rollback, and the programme-source registry. The frontend uses the remaining session-backed assessment and catalogue workflows.

Active profile responses expose `student.firstName`, `student.lastName`, and `personalAcademic.idNumber` instead of an LRN. `PUT /api/v1/student/profile` requires `firstName`, `lastName`, and an exactly eight-digit `idNumber`; it atomically synchronizes the split names, compatibility display name, and Student profile fields. This applies equally to local and Google-created Student accounts. Email remains read-only in this workflow. Profile responses do not expose the removed learning-profile questionnaire, selection options, strengths, growth areas, learning preferences, career-interest projection, or generated profile summary. Active profile and programme responses also do not expose SHS school, strand/track, graduation-year, recommended-strand, or strand-guidance fields. Recommendation result dimensions include competition-rank metadata so equal Student scores can be presented as shared positions. Programme recommendations expose dense display ranks, so an exact tie at rank 3 is followed by rank 4. New recommendation snapshots identify `PROPOSED-RIASEC-5-DENSE-RANKS`; existing immutable snapshots retain their stored data while the API derives consecutive display positions from their recorded rank groups.

Each recommendation course exposes its recorded `eligibilityGroup` and authoritative `eligibleForDeclaredGroup` flag. Clients use the false state only to present entrance-group review guidance; they must preserve the recorded RIASEC rank and match, keep the programme visible, and must not reinterpret the value as a pass/fail decision or admission rejection.

`PUT /api/v1/student/recommendations/{recommendationReference}/programmes/{programme}/feedback` creates or replaces the owning Student's response for a programme contained in that stored recommendation run. The JSON body requires integer `rating` from 1 through 5 and permits nullable `comment` up to 1,000 characters. The latest and historical recommendation responses return that Student's saved feedback on the matching programme. Ownership and programme membership are checked server-side; the operation never rewrites the recommendation snapshot.

`GET /api/v1/admin/feedback` is the dedicated Administrator feedback contract. For each programme, the service uses only the latest response from each distinct Student and publishes it beginning with the first saved response in the selected feedback-update date scope. `respondents` groups those programme responses internally by Student and returns only a current-view `respondentNumber`, response/comment counts, one-decimal average, latest saved date, compatibility `programmeFeedback`, and `resultSets`. Each result set has a presentation-only sequence number and date plus every programme from the immutable `ranked_courses` snapshot with recorded rank, code, name, exact match, and nullable published feedback. Neither recommendation scores nor ranks are recomputed. Respondent/result-set numbers are regenerated for the filtered response and are not account or assessment identifiers. Existing programme aggregates and nonblank `comments` remain for compatible aggregate consumers. Student names, emails, IDs, account identifiers, recommendation-run IDs, and assessment references are never included. `GET /api/v1/admin/reports` remains limited to assessment and engagement reporting and does not include feedback.
